# DiPlay Android 8.1 port — design

Date: 2026-10-07 · Branch: `android-8.1` on `UrvaSuthar/DiPlay` · Base: upstream 0.2.13 (`4bccb39`)

## Goal

Make DiPlay install and run on Android 8.0/8.1 (API 26/27) head units, starting with the
MAXLINK GD230 (Allwinner T3L, `armeabi-v7a`, build `t3_p1-eng 8.1.0 OPM1.171019.026`; its
Settings screen reports "Android 11", which is cosmetic). Android 9+ behaviour must not change.

## Constraints

- No GD230 is available for testing. Verification is CI + an API 27 emulator only.
- Builds run on GitHub Actions; the development Mac has no free disk space.
- Source/CI builds exclude the experimental accessory identity (upstream policy). A CI APK
  installs and runs but cannot complete a CarPlay handshake. This port does not add, extract
  or publish identity assets.
- License stays GPL-3.0 with upstream notices preserved.

## Changes

1. **SDK floor:** `minSdk` 28 → 26 in `mobile`, `common`, `automotive`; `shared` JNI
   `APP_PLATFORM` `android-28` → `android-26`. `compileSdk`/`targetSdk` unchanged.
2. **API guards:** `lint` (`NewApi`) lists every API 28+ call reachable from the app. Each gets an
   `SDK_INT` guard with an API 26 fallback, matching the existing guard style. No new abstraction
   layer. Where no fallback exists, the feature is hidden below API 28.
3. **Wireless on API 26/27:** offer Built-in car hotspot and Existing Wi-Fi / Same LAN.
   Hide Wi-Fi Direct below API 28 (its legacy path uses Android 9 APIs).
4. **IPv4 sockets:** sockets currently bound only to IPv6 (`::`) fall back to IPv4 when IPv6
   bind fails (crash reported in upstream issue #200).
5. **ABI:** no change; `shared` already builds `armeabi-v7a`.

Changes are small and commented `// android-8.1:` so upstream merges stay easy to review.

## Testing

New workflow `.github/workflows/android81.yml`:

1. Build `:mobile:assembleDebug`; run the upstream unit tests and `lintDebug` (catches API 28+
   regressions now that `minSdk` is 26).
2. Boot an API 27 `x86_64` emulator (`reactivecircus/android-emulator-runner`, KVM).
3. Smoke test via `adb`: install, launch via the launcher intent, wait 20 s, fail if the process is
   gone or logcat has a `FATAL EXCEPTION` for the app. Wireless-mode startup moved to the hardware
   checklist in `docs/ANDROID81.md` (UI automation on a CI emulator would be fragile).
4. Upload the APK, logcat and reports as artifacts.

The existing upstream `android.yml` must stay green (Android 9+ unaffected).

## Done when

- CI green on API 27 and on the existing upstream checks.
- The APK contains `lib/armeabi-v7a/`.
- `docs/ANDROID81.md` lists what is unverified (USB CarPlay, T3L decoder, 5 GHz Wi-Fi,
  Bluetooth handshake) and a short checklist for the first GD230 test.

## Out of scope

Custom features or branding, Wi-Fi Direct on 8.1, GD230 steering-wheel keys, accessory identity
handling, upstreaming (possible later via a PR to upstream issue #136).
